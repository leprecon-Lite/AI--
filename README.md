# AI-агент проверки качества кофейного сырья

Локальный прототип AI-агента для автоматической выбраковки кофейного сырья
по протоколам лабораторных испытаний.

**Заказчик:** ООО «Солярис» — производство по обжарке кофе.

---

## Что делает агент

Принимает на вход структурированный протокол испытаний (.csv или .xlsx),
сопоставляет фактические показатели с нормативами ГОСТ 32775—2014 и выдаёт:

- **🟢 Зелёный** — все параметры в норме, продукция годна.
- **🟡 Жёлтый** — отклонения в допустимых пределах (требует внимания).
- **🔴 Красный** — критические отклонения, продукция бракуется.

Дополнительно агент формирует краткий текстовый отчёт для оператора
с перечнем отклонений (фактическое vs нормативное значение) и может
объяснить технологический смысл норматива по RAG-запросу к GigaChat.

**Агент НЕ принимает решений** о переработке или списании — они остаются за комиссией.

## Требования

- **Docker Desktop** (Windows/macOS) или **docker + docker compose** (Linux) — для запуска через Docker.
- **Python 3.10+** — если запускаете без Docker.
- Доступ в интернет (для обращения к GigaChat API).
- Файл корневого сертификата Минцифры `russian_trusted_root_ca_pem.crt`
  уже лежит в папке `services/llm-gigachat/`.

## Быстрый старт через Docker (рекомендуется)

### 1. Клонируйте репозиторий

```bash
git clone https://github.com/<ваш_логин>/<ваш_репозиторий>.git
cd <ваш_репозиторий>
```

### 2. Подготовьте `.env`

```bash
cp .env.example .env
```

Откройте `.env` и укажите `GIGA_PASSWORD` — authorization key из
[developers.sber.ru](https://developers.sber.ru). Всё остальное можно оставить по умолчанию.

### 3. Запустите

```bash
docker compose up --build
```

Первый запуск займёт 3–5 минут (скачает образы и установит зависимости).
Последующие запуски — 10–20 секунд.

### 4. Откройте в браузере

| Сервис | URL |
|--------|-----|
| **Веб-интерфейс** | http://127.0.0.1:5500/demo.html |
| API шлюза (Swagger) | http://127.0.0.1:8000/docs |
| API AI-сервиса (Swagger) | http://127.0.0.1:8001/docs |

### 5. Остановите

```bash
docker compose down
```

Данные (`logs/`, `results.db`) сохраняются на хосте и не теряются при перезапуске.

## Использование

1. Откройте в браузере: **http://127.0.0.1:5500/demo.html**
2. Перетащите файл `batch_30.csv` (лежит в `services/llm-gigachat/`)
   в зону загрузки или нажмите, чтобы выбрать.
3. Нажмите **«Проверить»**.
4. Через 3–5 секунд появится:
   - Цветная плашка со статусом.
   - Текстовый отчёт от GigaChat.
   - Таблица со всеми партиями и перечнем отклонений.
   - Кнопка **«Почему это брак?»** рядом с каждым критическим отклонением.

**Тестовый файл:**
- `batch_30.csv` / `batch_30.xlsx` — 30 партий с разбросом статусов
  (ожидаемо: 6 красных, 6 жёлтых, 18 зелёных).

## Как это работает

```
Пользователь → demo.html (htmx)
    ↓ POST /ui/check/
Шлюз (порт 8000) → AI-сервис (порт 8001)
    ↓ POST /check/
AI-сервис:
    1. pandas читает CSV/XLSX
    2. GigaChat #1: семантический маппинг колонок → ID норматива
       (кэшируется в SQLite, повторно не вызывается)
    3. Python: детерминированная проверка каждой партии
    4. GigaChat #2: генерация сводного текстового отчёта
    5. Сохранение в SQLite
    ↓ HTML-фрагмент
Шлюз → Jinja2-шаблон → браузер

При клике «Почему это брак?»:
    demo.html → POST /explain/ → Шлюз → AI-сервис
    GigaChat #3: RAG-объяснение на основе текста ГОСТа
```

### Роли компонентов

| Компонент | Задача | Почему так |
|-----------|--------|-----------|
| **GigaChat** | Семантический маппинг колонок | Понимает смысл: `"W, %"` = `"влага"` |
| **GigaChat** | Генерация текстового отчёта | Пишет естественным языком |
| **GigaChat** | RAG-объяснение отклонений | Объясняет технологический смысл норматива |
| **Python** | Сравнение чисел с нормативами | Воспроизводимость, юридическая значимость |
| **Python** | Триградация | Не зависит от LLM, всегда одинаковый вердикт |
| **SQLite** | История проверок + кэш маппинга | Простота, работает локально без сервера |

**Ключевой принцип:** Python решает — GigaChat объясняет.

Если GigaChat недоступен — есть fallback на шаблонный отчёт.
Система продолжает работать.

## База знаний нормативов

Нормативы хранятся в файле `services/llm-gigachat/gost_32775_2014_rules.xlsx`
в машиночитаемом виде — таблица Excel.

**Колонки:**

| Колонка | Что содержит |
|---------|--------------|
| `id` | Уникальный идентификатор пункта ГОСТа |
| `standard` | Название стандарта (ГОСТ 32775—2014) |
| `clause` | Номер пункта/таблицы |
| `category` | Категория показателя |
| `parameter` | Полное название параметра |
| `aliases` | Синонимы через `;` (для маппинга) |
| `operator` | `не более` / `не менее` / `от ... до` / `требование` / `согласно` / `не допускается` |
| `value_min` | Минимум (для `не менее` и `от ... до`) |
| `value_max` | Максимум (для `не более` и `от ... до`) |
| `value_text` | Строковое значение (для нечисловых операторов) |
| `unit` | Единица измерения |
| `method_ref` | Ссылка на метод контроля |
| `text` | Полный текст пункта ГОСТа (используется в RAG) |

Файл **редактируется в Excel** — технолог может поправить допуск
без правки кода.

**Перегенерация XLSX из исходного JSON:**

```bash
cd services/llm-gigachat
python make_rules_xlsx.py
```

## Экономия токенов GigaChat

При загрузке 30-строчного файла GigaChat вызывается **всего 2 раза**:

1. Маппинг колонок (кэшируется в SQLite).
2. Сводный отчёт (только агрегат + первые 10 проблемных строк, не все 30).

При повторной отправке файла с теми же колонками — **1 раз** (только отчёт).
Маппинг берётся из кэша.

RAG-объяснение вызывается **только по клику пользователя** на кнопку
«Почему это брак?» — то есть не тратит токены при обычной проверке.

## Юнит-тесты

```bash
pip install pytest
cd services/llm-gigachat
python -m pytest tests/ -v
```

**Ожидаемый результат:** `62 passed`.

Покрывают:
- Парсинг чисел (`5,5` / `5.5` / `5.5 %` / NaN / None)
- Все операторы: `не более`, `не менее`, `от ... до`, `не допускается`
- Граничные значения: `actual == min`, `actual == max`
- Зона warning (±5% от границы)
- Fuzzy-поиск по алиасам
- Агрегация статуса файла

## Возможные проблемы

| Проблема | Решение |
|----------|---------|
| `401 Unauthorized` | Проверьте `GIGA_PASSWORD` в `.env` |
| `404 Model not found` | Смените модель в `.env` на `GigaChat` или `GigaChat-Pro` |
| `SSL certificate problem` | Проверьте наличие `russian_trusted_root_ca_pem.crt` |
| `Address already in use` | `taskkill /F /IM python.exe` (Windows) |
| `TemplateNotFound` | Проверьте, что папка `templates/` лежит рядом с `main.py` |
| `htmx:invalidPath` | Проверьте meta-тег `htmx-config` в `demo.html` |
| `port is already allocated` (Docker) | Остановите локальные сервисы перед `docker compose up` |
| `Cannot connect to Docker daemon` | Запустите Docker Desktop |

## Лицензия и ограничения

Прототип разработан для хакатона. Агент выполняет только первичный скрининг —
решения о переработке или списании продукции принимает комиссия.

**GigaChat не выносит вердикт о качестве.** Он решает три интеллектуальные задачи:
маппинг нестандартных названий колонок, генерация текстового отчёта и
RAG-объяснение технологического смысла норматива. Финальный вердикт
(годно / требует внимания / брак) даёт детерминированный классификатор на Python —
это гарантирует воспроизводимость и юридическую значимость решения.
